# 12. HISTORICAL DEMAND FORECASTING

This section forecasts future demand only when sufficient actual historical sales data exists.

Preferred inputs:

- Actual monthly orders.
- Actual monthly revenue.
- Monthly website traffic.
- Monthly conversion rates.
- Historical advertising spend.
- Historical CAC.
- Sales-channel information.
- Stock availability.
- Promotion periods.
- Seasonal sales patterns.

### A. Data preparation

Before forecasting:

1. Check data completeness.
2. Identify missing months.
3. Identify stockout periods.
4. Identify promotional spikes.
5. Identify changes in selling price.
6. Separate paid and organic traffic where possible.
7. Separate country-level sales.
8. Identify unusual one-off events.

Do not interpret stockout periods as zero customer demand.

### B. Forecasting methods

Select the simplest suitable statistical method.

**Method 1 — Moving Average**

Use previous observations to estimate future demand.

`Forecast = Sum of Selected Historical Observations / Number of Observations`

Useful as a simple baseline when the series is reasonably stable.

**Method 2 — Exponential Smoothing (ETS)**

Give more weight to recent observations.

Useful when demand changes over time and the historical data supports the selected model.

**Method 3 — ARIMA**

Consider historical patterns, trends and autocorrelation.

Use only when sufficient consistent observations exist.

**Method 4 — Seasonal ARIMA (SARIMA)**

Use when recurring seasonal behaviour is supported by sufficient historical observations.

For monthly annual seasonality, normally require at least two complete seasonal cycles before attempting a meaningful seasonal evaluation.

### C. Data sufficiency rules

Use the following as practical research guidance, not universal statistical guarantees:

| Available monthly observations | Permitted analysis |
|---|---|
| 0–2 | No time-series forecast |
| 3–11 | Simple baseline or moving average, low confidence |
| 12–23 | Evaluate simple trend and ETS methods |
| 24+ | Evaluate seasonal methods where recurring patterns exist |

A model must be selected based on data quality and suitability, not simply because the software supports it.

Do not use machine learning or complex models when a simple baseline is more appropriate.

# 13. FORECAST ACCURACY AND BACKTESTING

When historical actual sales and historical forecasts are available, measure forecast performance.

Use rolling-origin out-of-sample backtesting.

### Weighted Absolute Percentage Error (WAPE)

`WAPE = (Sum of Absolute Actual-Forecast Errors / Sum of Actual Sales) × 100`

Example:

- Actual orders: 80.
- Forecast orders: 100.
- Absolute error: 20.

`WAPE = (20 / 80) × 100 = 25%`

Lower WAPE indicates better forecast accuracy.

### Backtesting requirements

- Test on observations not used to fit the model.
- Preserve chronological order.
- Compare against a simple baseline.
- Record the test period.
- Record the number of observations.
- Report the actual and forecast values.
- Avoid data leakage.
- Do not use in-sample accuracy as proof of forecasting performance.

If total actual sales are zero, report WAPE as `NOT APPLICABLE`.

If historical forecasts do not exist, report:

`NOT AVAILABLE — NO HISTORICAL FORECAST COMPARISON`

Do not fabricate a historical accuracy score.
